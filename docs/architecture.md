# One product, one backend

The public website serves `/`, `/u/[username]`, `/projects/[slug]`, and `/events/[slug]`. The responsive `/app` is both the desktop app and installable mobile PWA. Both use the same Next.js API and Supabase PostgreSQL/Auth/Storage.

QR frames are decoded on the device: native BarcodeDetector first, dynamic ZXing fallback second. Camera data never makes a network round-trip. This keeps the latency-sensitive operation close to the camera. Introducing Go or Python for frame processing would add uploads, network latency, and operational complexity without helping this workload.

Maps, the scanner, and app resource screens use dynamic imports. Maps do not load on the landing/dashboard. Public metadata and pages are server rendered; fonts and cropped illustrative avatars are self-hosted. The build produces optimized static marketing/auth/app-shell pages and dynamic resource/API routes.

Guest records are persisted immediately in localStorage; local audio is held in IndexedDB. A signed-in workspace has an account-specific cache and durable outbox. Mutations include only changed records and explicit deletion tombstones. The API verifies session and origin, validates payloads, rate limits through PostgreSQL, and invokes one RLS-protected transaction. Stable meeting IDs merge histories; canonical profile contact IDs reconcile independently saved duplicates. Cloud state is acknowledged only after the transaction succeeds.

Connection entry is scan-first. Camera startup is tied to the scanner lifecycle and stale permission requests release their tracks after navigation. NFC reading is triggered by a deliberate button tap and canceled with an AbortSignal. A successful read stops the hardware and saves one contact/meeting; repeated callbacks from the same scan are ignored. Saved Connect IRL source URLs allow a known contact to be recognized again offline. New public profiles require a network lookup; unknown external URLs remain clearly labeled as link-only contacts. The private current-event preference and exact meeting timestamp travel through the same outbox and transaction as other workspace data.

Google is the primary authentication choice; other methods are progressively disclosed. The callback directs first-time accounts to three-step profile setup and existing accounts to the workspace. Presence of a saved profile prevents repeated onboarding. Profile links can be edited later; current-event selection stays outside public profile JSON and does not create a venue check-in.

The public brand is Connect IRL at `connectirl.xyz`. Legacy localStorage/IndexedDB/cache namespaces remain unchanged so a rebrand does not discard existing device data. Root/login/signup requests with an auth cookie verify the user on the server and redirect signed-in members to `/app`, copying refreshed cookies and preventing redirect caching. First-time visitors do not make a root auth round trip. Email OTPs are verified by Supabase; Resend supplies SMTP transport with a branded token template, rather than a separate verification database.

Migration 005 records a recipient-only connection receipt after a public-profile contact is committed. It contains account references and a timestamp, not private meeting/event data. The invoker sync transaction still owns the contact mutation; a narrowly scoped trigger writes deduplicated receipts, applies bilateral blocks/public visibility, and bounds sends. Only the recipient can read or mark a receipt read. Receiving a receipt does not automatically save a contact back. Active QR sharing polls every two seconds while visible; other screens poll less often or on focus. Both parties get a finite SVG/CSS success sequence from actual local save/remote receipt state. The outgoing animation is independent of network sync and never gates the next action.

Public profile JSON contains only intentionally public profile fields. Contact snapshots and notes reside in owner-only tables. Normalized meeting/tag rows and JSON record representations are written atomically. Composite foreign keys prevent assigning another owner's contact to a reminder or voice note. Service-role access is never present in client code. The only application service-role endpoint deletes the authenticated user's own storage folders and account.

Collaboration uses a database transaction for every consent transition. Clients cannot write invitations, requests, or memberships directly. Only the owner can accept requests, invite builders, change role labels, or remove others; invitees must accept before gaining membership. Members may leave, and private-project read access ends with membership. Editing remains owner-only. Participant-only inboxes expose public identities and small project summaries rather than private contact books. Workspace screens remount when account identity changes so loaded private state cannot carry across accounts.

Venue discovery is authenticated and queries active, voluntary check-ins joined to public, discoverable profiles. Filtering, pagination, and bilateral blocking run in PostgreSQL. Clients debounce searches, cancel stale requests, remove expired results, and refresh on demand. No GPS coordinates, private notes, or external attendee lists are returned. Both workflows load only on their relevant app screens.

Events are verified, versioned records. Moderator actions use the server-side SQL Editor workflow. Semantic search, transactional email reminders and automated event imports remain extension points.
