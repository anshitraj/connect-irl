# Resend + Supabase email verification

Connect IRL uses one Supabase account/session for Google OAuth, X OAuth and email sign-in links. Resend transports the verification email through Supabase's custom SMTP setting. No Resend API key belongs in the frontend or `NEXT_PUBLIC_` variables.

1. In Resend, add and verify `connectirl.xyz` (or a dedicated sending subdomain). Add the exact DNS records shown by Resend at your domain's DNS host. Use its generated SPF/DKIM records; do not guess DNS values or replace unrelated mail records.
2. Create a Resend API key for the sending domain. In Supabase Auth's Email/SMTP settings, enable custom SMTP: host `smtp.resend.com`, port `465`, username `resend`, password the Resend API key. Choose sender name **Connect IRL** and sender address **hello@connectirl.xyz** after that sending domain is verified. This address sends verification emails; set `NEXT_PUBLIC_CONTACT_EMAIL` separately to an inbox you actually monitor.
3. Enable the Email provider in Supabase. Set an appropriate link expiry and raise the emails-per-hour rate limit (it is low until custom SMTP is on). Email sign-in is link-only: the user taps the button in the email and `/auth/confirm` signs them in. There is no code to type. The login screen offers a 60-second resend cooldown, changing the email address, and shows a notice when a link has expired.
4. Replace **both** Supabase email templates (Authentication → Emails → Templates). They share one design: an animated Connect IRL logo header, a QR-scan illustration, and a one-tap button.
   - **Magic Link** (returning users): paste `supabase/templates/magic-link.html`, subject **Your Connect IRL sign-in link**.
   - **Confirm signup** (brand-new users): paste `supabase/templates/confirm-signup.html`, subject **Welcome to Connect IRL — confirm your email**. It adds a three-step "Scan, Save, Follow up" strip.

   Supabase uses these for `signInWithOtp`. The button links to `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}`, and the server redeems the hash with `verifyOtp` (type `email`), so the link works in whichever browser or device opens it, including mail apps' built-in browsers. This is why the Supabase **Site URL** must be exactly `https://connectirl.xyz`. Do not use `{{ .ConfirmationURL }}` (a PKCE link only works in the browser that asked for it) and do not remove the `{{ .TokenHash }}` placeholder. The user verifies ownership by opening the link, with no password to create.

   The HTML files are generated, not hand-edited. Change `src/lib/email/` and run `npm run email:templates`; `npm test` fails if the pasted files drift from the source. The images are served from `https://connectirl.xyz/email/` (`public/email/`), so **deploy to production before testing the emails**, or the header and illustration will not load. Regenerate the animated art with `npm run email:assets` (needs `ffmpeg`). Frame 1 of every GIF is a complete picture, which is what Outlook desktop shows.
5. Set Supabase Site URL to `https://connectirl.xyz`, allow `https://connectirl.xyz/auth/callback`, and configure the corresponding Vercel environment variables. Keep development callbacks explicitly allowed only where needed. Google OAuth remains a separate primary sign-in option using the same Supabase accounts; it does not require an email step.
6. Test with a real mailbox: open the link on the same phone and on another device, try a reused or expired link, resend behavior, existing/new accounts, and returning to the root while signed in. Confirm the production email arrives through Resend and sender authentication passes.

## "Someone connected with you" emails

When a signed-in member saves another member's public profile, the recipient gets an email from **Connect IRL <hello@connectirl.xyz>** with the sender's public name, headline and photo, and a link to their profile. It never includes notes, event or meeting details.

1. Apply migration `202610260007_connection_emails.sql` (it is already part of `supabase/setup-all.sql`). It adds an `emailed_at` marker to connection receipts, a per-account `connection_emails` opt-out, and the service-only `claim_connection_emails` function.
2. In Resend, create a second API key with **Sending access** for this domain and set it as `RESEND_API_KEY` in Vercel (server only, no `NEXT_PUBLIC_` prefix). `SUPABASE_SERVICE_ROLE_KEY` must also be set. Optionally set `EMAIL_FROM`; it defaults to `Connect IRL <hello@connectirl.xyz>`. With `RESEND_API_KEY` unset, no connection emails are sent and nothing else changes.
3. Nothing else to configure. After each workspace sync that includes contacts, the server asks the database which receipts are due. The database applies the rules (both profiles public, no blocks in either direction, recipient has a confirmed email and has not opted out, receipt under an hour old) and marks each receipt emailed in the same statement, so concurrent syncs cannot double-send. A failed send releases the receipt so the next sync retries it. Resend also receives an idempotency key per receipt.
4. Every email carries a signed **Turn off connection emails** link and `List-Unsubscribe` headers, including one-click unsubscribe. The link opens a confirmation page (so mail scanners cannot unsubscribe anyone), and the confirmation can be undone from the same page. Links are signed with `SUPABASE_SERVICE_ROLE_KEY`; rotating that key invalidates links in old emails.

Preview emails locally by rendering `connectionEmail()` from `src/lib/email/connection-email.ts` with sample data. The tests in `tests/unit/email-templates.test.ts`, `tests/unit/notify-connections.test.ts` and `tests/database/connection-emails.test.ts` cover rendering and escaping, delivery and retry, and the eligibility rules.

The templates, sending path and verification flow are implemented and tested locally. DNS, Resend, Supabase SMTP, real email delivery, and hosted OAuth still need dashboard configuration and end-to-end verification in a real mailbox (check Gmail, Apple Mail and Outlook, light and dark).

References checked 26 October 2026: [Resend's Supabase SMTP guide](https://resend.com/docs/send-with-supabase-smtp), [Supabase email OTP guide](https://supabase.com/docs/guides/auth/auth-email-passwordless).
